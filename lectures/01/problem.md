# 第1回 演習・宿題：開発環境を整え、LLMに質問する

## この回のゴール

- 自分の fork を Codespaces で開き、Gemini API を呼び出せる
- GitHub Copilot でコードを少し直せる
- 作業ブランチから PR を出して提出できる（以降の回もこの流れで提出する）

## 準備するもの

- GitHub の個人アカウント（会社が管理するアカウントは、組織の設定で Codespaces や Copilot が使えないことがあります）
- Google の個人アカウント（会社の Google Workspace アカウントは、管理者の設定で AI Studio が使えないことがあります）

## 演習（45分）

### 1. 講座 repo を fork する

講座 repo の右上の **Fork** から、自分のアカウントに fork を作ります。以降の作業はすべて自分の fork で行います。

### 2. Gemini API キーを発行する

[Google AI Studio](https://aistudio.google.com/apikey) で API キーを作成し、コピーします。

> APIキーは秘密情報です。コードやチャット、コミットに貼らないでください。漏れた場合は AI Studio でキーを削除し、作り直してください。

### 3. Codespaces secret に登録する

GitHub の **Settings → Codespaces → Secrets → New secret** で次のように登録します。

- Name: `GEMINI_API_KEY`
- Value: 手順2のキー
- Repository access: **自分の fork** を選ぶ

> Codespaces を起動する前に登録してください。起動後に登録した場合は、Codespaces の再起動が必要です。

### 4. Codespaces を起動する

自分の fork で **Code → Codespaces → Create codespace on main**。初回は環境の準備に数分かかります。ターミナルで次を実行し、テストが通ることを確認します。

```bash
uv run pytest -q
```

### 5. 素のLLMに質問する

```bash
uv run python -m app.ask "LoRAとは何ですか？"
uv run python -m app.ask "AIE2026の講座の宿題にある「3レベル」とは何ですか？"
```

1つ目は一般的な用語なので、おおむね正しい答えが返ります。2つ目は講座に固有の「宿題の3レベル」について質問します。素のLLMは講座のことを知らないため、「分からない」と答えるか、一般論でもっともらしく答えます。正しい内容は `data/glossary.json` の `homework-levels` にあります。モデルの答えと比べてみましょう。

余裕があれば、ほかの講座に固有の質問も試してください。同じ質問でも実行ごとに答えが変わること、知らないことでも確信を持って答えることがあることに注目しましょう。

```bash
uv run python -m app.ask "AIE2026の講座で使う「lecNN-start タグ」とは何ですか？"
uv run python -m app.ask "AIE2026の第2回では何を学びますか？"
```

### 6. Copilot でトークン数を表示させる

`app/ask.py` の `TODO(第1回 演習)` の場所で、入力トークン数と出力トークン数を表示するよう改修します。Copilot の補完やチャットを使ってかまいません。提案されたコードは、読んで理解してから採用してください。

### 7. ブランチを作って PR を出す

```bash
git switch -c lec01
# lectures/01/answer.md を書く
git add -A
git commit -m "第1回 演習"
git push -u origin lec01
```

GitHub の自分の fork で、`lec01` → `main` の PR を作成します。**base repository が自分の fork になっていることを確認してください**（講座 repo に PR を出さないこと）。

### 8. Codespaces を停止する

左下の「Codespaces」→ **Stop Current Codespace**。起動したままだと無料枠を消費し続けます。

**LoRA（ローラ）**とは、「Low-Rank Adaptation（低ランク適応）」の略で、AI（特に大規模言語モデルや画像生成AI）の**効率的なファインチューニング（追加学習）技術**のことです。

簡単に言うと、**「AIの頭脳全体を書き換えるのではなく、付箋を貼るように少しの追加学習だけで、AIのキャラクターや画風をガラリと変える技術」**です。

---

### 1. 従来の課題とLoRAのすごさ
これまでのAIの学習方法には大きな問題がありました。
* **従来の学習:** AIの数億〜数千億あるすべてのパラメータ（脳細胞のようなもの）を調整するため、**莫大な計算パワー（高性能なGPU）と時間、大容量のストレージ**が必要でした。
* **LoRAの場合:** AIの本体（ベースモデル）は**一切いじりません**。その代わりに、AIの重要な部分の横に「小さなメモ用紙（追加のネットワーク）」を取り付け、そこだけを学習させます。

### 2. LoRAの主なメリット
1. **圧倒的に軽い（データ容量が小さい）**
   * 従来の学習データが数GB〜数十GBあるのに対し、LoRAのファイルは**数MB〜数百MB程度**と非常に軽量です。
2. **学習コストが低い**
   * 高価なパソコンがなくても、個人のゲーミングPCなどで短時間（数分〜数時間）で学習させることができます。
3. **簡単に切り替えられる**
   * 「アニメ風にするLoRA」「特定の人物を描くLoRA」「特定の口調にするLoRA」などを複数作っておき、必要に応じて着せ替え人形のようにパッと切り替えて使えます。

### 3. どんなところで使われているの？
現在、特に以下の分野で大流行しています。

* **画像生成AI（Stable Diffusionなど）:**
  特定のキャラクターやアニメ調、リアル調など、特定の画風や人物をAIに学習させて出力させるために必須の技術となっています。
* **大規模言語モデル（LLM / ChatGPT系など）:**
  AIに特定の専門知識を教え込んだり、特定のキャラクター（「ツンデレなアシスタント」など）の口調を真似させたりするために使われます。

### まとめ
LoRAとは、**「AIの本体を改造せず、手軽に・安価に・特定の個性を後付けするための省エネ技術」**です。AIを自分好みにカスタマイズするハードルを劇的に下げた革命的な手法として、現在のAIブームを支える重要技術の一つとなっています。

---

### 1. なぜLoRAが必要なのか？（従来の問題点）

従来の学習方法（フルファインチューニング）では、AIモデル全体の膨大なパラメーター（数億〜数千億個）をすべて書き換える必要がありました。
これには以下のような問題がありました：

*   **巨額のコスト:** 数十万円〜数千万円クラスの超高性能GPUが必要。
*   **膨大な容量:** 学習後のモデルファイルが非常に大きい（数十GB〜数百GB）。
*   **管理の難しさ:** 目的ごとに巨大なモデルファイルを丸ごと保存・管理しなければならない。

### 2. LoRAの仕組み（例え話）

LoRAは**「元のモデル（ベース）には手を付けず、差分データだけを小さく作って上乗せする」**というアプローチを取ります。

*   **イメージ:**
    巨大な「辞書（ベースモデル）」があるとします。
    *   **従来の学習:** 辞書全体を書き直す（大変！）。
    *   **LoRA:** 辞書本体はそのままにして、**「付箋（LoRA）」**に必要な専門用語や修正点だけを書いて貼っていくイメージです。

元のモデルの数値を固定（フリーズ）し、小さく分解した行列（Low-Rank Matrix）だけを学習させるため、計算量と必要なメモリを劇的に減らすことができます。

---

### 3. LoRAの主なメリット

1.  **ファイルサイズが圧倒的に軽い**
    元のモデルが数十GBあっても、LoRAのファイルは**数MB〜数百MB程度**で済みます。保存やインターネットでの配布が非常に簡単です。
2.  **家庭用PC（GPU）でも学習・実行が可能**
    VRAM（ビデオメモリ）の消費量が大幅に減るため、市販のグラフィックボード（NVIDIA RTX 3060 / 4060など）でも十分に学習を行えます。
3.  **簡単に「着脱・切り替え」ができる**
    1つのベースモデルに対して、「絵柄AのLoRA」「キャラクターBのLoRA」のように、付け替えるだけで出力の傾向を自由に変えられます。複数のLoRAを同時に適用（合成）することも可能です。

---

### 4. 主な活用例

LoRAは主に以下の2つの分野で大活躍しています。

#### ① 画像生成AI（Stable Diffusionなど）
*   **特定キャラクターの再現:** 好きなキャラやオリジナルのキャラを正確に描かせる。
*   **画風・絵柄の学習:** 水彩画風、アニメ風、特定のアートスタイルを再現する。
*   **衣装・ポーズ・背景の固定:** 特定の服やシチュエーションを生成しやすくする。

#### ② 文章生成AI / LLM（Llama, GPTなどのオープンソースモデル）
*   **特定の口調やキャラ付け:** 「語尾に『〜ニャ』をつける」「語り口をツンデレにする」など。
*   **専門知識の学習:** 医療、法律、社内マニュアルなどの特定分野の知識を効率よく学習させる。
*   **特定フォーマットでの出力:** JSON形式や特定のレスポンス形式を厳格に守らせる。

### 1. なぜLoRAが必要なのか？（背景）
ChatGPTのような大規模言語モデル（LLM）や、Stable Diffusionのような画像生成AIは、数億〜数千億個ものパラメータ（重み）を持っています。

これらを特定の用途（例：社内専用のチャットボットにする、特定の絵柄を学習させる）に合わせて追加学習させる場合、従来は**すべてのパラメータを更新（フルファインチューニング）**する必要がありました。
しかし、それには以下の問題がありました。

* **膨大な計算コスト:** 高価なスーパーコンピューターや大量のGPUが必要。
* **巨大なファイルサイズ:** 学習するたびに、元の巨大なモデル（数GB〜数百GB）を丸ごと保存し直す必要がある。

### 2. LoRAの仕組み（例え話）
LoRAは、**「元のモデル本体は一切いじらず（固定/フリーズ）、差分（追加の知識）だけを小さなパーツとして外付けする」**というアプローチを取ります。

* **従来の学習:** 分厚い辞書の全ページを書き換えて、新しい辞書を丸ごと一冊作り直すようなもの。
* **LoRA:** 辞書本体には手を触れず、**「追加の付箋（メモ書き）」**を数枚挟むだけ。

数学的には、巨大な行列の更新を「小さな2つの行列の掛け算（低ランク行列）」に分解して計算量を劇的に減らしています。

### 3. LoRAのメリット

1. **データサイズが劇的に小さい**
   元のモデルが数GB〜数十GBあるのに対し、LoRAのファイルは**数MB〜数百MB程度**で済みます。
2. **普通のパソコン（GPU）でも学習できる**
   メモリ消費量が非常に少ないため、一般向けのゲーミングPC（GeForce RTXシリーズなど）でも追加学習が可能です。
3. **着せ替えや組み合わせが自由**
   「ベースのモデル」を1つ持っておけば、用途に合わせて「LoRA A（特定のキャラクター）」「LoRA B（特定の画風）」のように、カセットを差し替えるように適用できます。複数のLoRAを同時に重ねがけすることも可能です。

### 4. 主な活用例

* **画像生成AI（Stable Diffusionなど）**
  * 最も一般的に使われている分野です。特定のキャラクター、特定の絵師の画風、特定のポーズや衣装などを再現するための「追加データ」として、世界中で無数のLoRAが共有されています。
* **大規模言語モデル（LLM）**
  * Llama 3などのオープンなモデルに対して、「医療専門用語に特化させる」「関西弁で話すようにする」「プログラミングの特定言語に強くする」といったカスタマイズを施す際に多用されています。
